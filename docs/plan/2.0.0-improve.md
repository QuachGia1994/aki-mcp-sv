## Tóm tắt
Chính thức chốt nâng cấp lên **v2.0.0** (major breaking changes).
Kế hoạch tái cấu trúc toàn diện theo góc nhìn **Non-dev / Packaged**: loại bỏ phụ thuộc môi trường dev (`git`, `npm`, `node` trong runtime app logic) và các package bên thứ ba.
Viết lại hoàn toàn các công cụ (đặc biệt là native filesystem tools tinh gọn học hỏi từ DeepSeek harness) gom về một khối in-process, xóa bỏ nút restart hub, giúp app đóng gói siêu gọn và tiến tới mục tiêu **Single Portable Unix Executable File** (hoàn toàn khép kín, zero-dependency).

## 7. Native Filesystem Tools & Hợp nhất Single Process (Loại bỏ mcp-hub & Restart Hub)
- **Bối cảnh**: Hiện server chạy theo mô hình đa tiến trình với `mcp-hub` điều phối và `@modelcontextprotocol/server-filesystem` chạy qua child process riêng (`npx`). Do package này chỉ nhận thư mục cấp quyền qua CLI args lúc khởi động, nên khi thêm/sửa folder bắt buộc phải có nút *"Apply to file tools (restarts hub)"*, gây gián đoạn kết nối session.
- **Kế hoạch hợp nhất (kế thừa từ `unify-mcp-tools-single-process.md`)**:
  1. **Loại bỏ `mcp-hub` & cổng `19999`**: Đưa toàn bộ việc đăng ký tool về `McpServer` in-process (dùng `StreamableHTTPServerTransport` của SDK hoặc `InMemoryTransport`), bảo toàn cơ chế multiplexing session của claude.ai (tham chiếu `docs/plan/done/bridge-session-churn.md`).
  2. **Native Filesystem Tools**: Tự viết module filesystem native tinh gọn (học hỏi triết lý [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) & Claude Code), tích hợp trực tiếp vào in-process server, đọc quyền truy cập động qua `roots.js:getRoots()` từ `setting.json`.
  3. **Xóa bỏ nút Restart Hub**: Thay đổi thư mục có hiệu lực ngay tại runtime mà không cần khởi động lại hub hay ngắt kết nối client.
  4. **Tối ưu RAM**: Đưa toàn bộ server về **1 tiến trình Node.js duy nhất**, giảm baseline RAM xuống ~40MB.
- **Done**: 4 tiến trình → 1. `filesystem-mcp.js` giữ 7 tool (`read_text_file`, `write_file`, `edit_file`, `create_directory`, `move_file`, `get_file_info`, `list_allowed_directories`), bỏ 7 tool cũ của `@modelcontextprotocol/server-filesystem` (`read_file` alias, `list_directory*`, `directory_tree`, `search_files` — đã có `find_path`/`search_content` thay thế, `read_multiple_files`, `read_media_file` — không dùng thực tế, dễ thêm lại nếu cần). Tên tool giữ nguyên `local__*` (áp qua wrapper trong `tools-server.js`, không đổi tên lần hai).
- **Runtime verification (2026-08-21)**: đo trên `npm start` thật (chi tiết `CHANGELOG.md` [Unreleased]). Session-multiplexing, OAuth DCR round-trip, và folder live-reload không-cần-restart đều pass.
- **RAM root-caused (2026-08-21)**: đo ban đầu ~92MB, không đạt ~40MB. Cô lập từng subsystem bằng `process.memoryUsage()`: Node+zod trần ≈ 40MB (đúng target gốc); import `@modelcontextprotocol/sdk`'s `McpServer` cộng thêm **+27MB cố định** (types.js build toàn bộ zod schema của MCP protocol kể cả resources/prompts/sampling không dùng tới — không có subpath nhẹ hơn trong package.json exports của SDK, không sửa được từ phía repo này). 5 module tool tự viết chỉ cộng ~3MB. ~22MB còn lại do `update-check.js` gọi `fetch()` lúc boot (Node lazy-init `undici`) — đã fix bằng `node:https`, đo lại real run: **~72.6MB**. Kết luận: mục tiêu ~40MB trong bản kế hoạch gốc không tính đến chi phí cố định của SDK chính thức; ~72-76MB mới là sàn thực tế khi còn dùng SDK này, không phải regression cần tiếp tục săn.
