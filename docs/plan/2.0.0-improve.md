# 2.0.0 — Architecture Evolution & Standalone Single Executable Vision

> status: open · not started

## Tóm tắt
Chính thức chốt nâng cấp lên **v2.0.0** (major breaking changes).
Kế hoạch tái cấu trúc toàn diện theo góc nhìn **Non-dev / Packaged**: loại bỏ phụ thuộc môi trường dev (`git`, `npm`, `node` trong runtime app logic) và các package bên thứ ba.
Viết lại hoàn toàn các công cụ (đặc biệt là native filesystem tools tinh gọn học hỏi từ DeepSeek harness) gom về một khối in-process, xóa bỏ nút restart hub, giúp app đóng gói siêu gọn và tiến tới mục tiêu **Single Portable Unix Executable File** (hoàn toàn khép kín, zero-dependency).

## 1. Chuẩn hóa userData (biểu hiện: aki-mcp-status.json)
Chi tiết + rà soát đầy đủ: `~/.aki/mcpsv/task/status-path/plan.md`. Tóm tắt: `update-check.js` STATUS_PATH ghi ngoài `USER_DIR`; `panel-client.js:88` text theo path cũ. Chờ confirm: xóa file cũ hay giữ song song; bump patch/minor.

## 2. Cải thiện flow checkupdate
Bug xác nhận qua code: `writeStatusFile()` chỉ chạy 1 lần lúc boot (`start.js:93`). Nút update / `refreshLocalVersions()` trong `panel.js` (dòng ~199-243) chỉ sửa `updateInfo` in-memory để render panel đúng — **không ghi lại STATUS_PATH**. Kết quả: panel web hiện đúng ngay sau update, nhưng `~/.aki/aki-mcp-status.json` (nguồn AI session đọc) vẫn stale tới khi restart process.
Fix: gọi `writeStatusFile()` ngay sau mỗi `refreshLocalVersions()` và sau khi install.sh chạy xong trong panel.js.

## 3. Triết lý gói packaged / non-dev & Hướng tới Single Executable File (BREAKING) — ghim nguyên văn owner
> chuẩn hóa trọn vẹn triết lý sử dụng: lấy góc nhìn là bản đóng gói tải về từ trang release: dọn mọi lệnh git và lệnh nodejs - những lệnh phụ thuộc môi trường dev. chiến lược này ưu tiên focus vào user sử dụng tiện lợi, non dev. giảm mọi phụ thuộc và sự phức tạp cho users. điều này kéo theo các lệnh check/install update sử dụng http thuần, các native function.

Liên quan: `docs/plan/done/standalone-release-delivery.md` (đã ship Node-less delivery framework, 1.9.0) — mục này nâng tầm:
- Audit toàn bộ `scripts/` tìm chỗ shell-out `git`/`npm`/`node` bên trong app logic (vd `panel.js` install.sh flow dùng `bash install.sh` + git), thay bằng HTTP thuần (đã có sẵn ở `update-check.js` qua `fetch`) + native fs, không đòi hỏi dev toolchain trên máy user.
- Tái cấu trúc và tự chủ hoàn toàn mã nguồn các công cụ nội bộ để mở đường đóng gói app thành **một file thực thi duy nhất (single portable unix executable file)** không cần node_modules rời rạc.

## 4. Cân nhắc bỏ .env (BREAKING) — ghim nguyên văn owner
> Cân nhắc loại bỏ luôn cơ chế .env, mọi thứ để cho app setting quản lý, cứ start rồi mọi chuyện setup tính sau, quản lý một cách tự động bởi chính main process, giảm tối đa sự phức tạp cho users

Chesterton's Fence: `docs/plan/done/env-file-configuration.md` đã ship .env có chủ đích (multi-user/profile config, custom subdomain/ports/data-dir). Trước khi bỏ: đọc lại lý do gốc, xác nhận app-setting + main-process-managed startup thay thế đủ mọi use-case đó, không mất khả năng multi-profile.

## 7. Native Filesystem Tools & Hợp nhất Single Process (Loại bỏ mcp-hub & Restart Hub)
- **Bối cảnh**: Hiện server chạy theo mô hình đa tiến trình với `mcp-hub` điều phối và `@modelcontextprotocol/server-filesystem` chạy qua child process riêng (`npx`). Do package này chỉ nhận thư mục cấp quyền qua CLI args lúc khởi động, nên khi thêm/sửa folder bắt buộc phải có nút *"Apply to file tools (restarts hub)"*, gây gián đoạn kết nối session.
- **Kế hoạch hợp nhất (kế thừa từ `unify-mcp-tools-single-process.md`)**:
  1. **Loại bỏ `mcp-hub` & cổng `19999`**: Đưa toàn bộ việc đăng ký tool về `McpServer` in-process (dùng `StreamableHTTPServerTransport` của SDK hoặc `InMemoryTransport`), bảo toàn cơ chế multiplexing session của claude.ai (tham chiếu `docs/plan/done/bridge-session-churn.md`).
  2. **Native Filesystem Tools**: Tự viết module filesystem native tinh gọn (học hỏi triết lý [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) & Claude Code), tích hợp trực tiếp vào in-process server, đọc quyền truy cập động qua `roots.js:getRoots()` từ `setting.json`.
  3. **Xóa bỏ nút Restart Hub**: Thay đổi thư mục có hiệu lực ngay tại runtime mà không cần khởi động lại hub hay ngắt kết nối client.
  4. **Tối ưu RAM**: Đưa toàn bộ server về **1 tiến trình Node.js duy nhất**, giảm baseline RAM xuống ~40MB.
- **Done**: 4 tiến trình → 1. `filesystem-mcp.js` giữ 7 tool (`read_text_file`, `write_file`, `edit_file`, `create_directory`, `move_file`, `get_file_info`, `list_allowed_directories`), bỏ 7 tool cũ của `@modelcontextprotocol/server-filesystem` (`read_file` alias, `list_directory*`, `directory_tree`, `search_files` — đã có `find_path`/`search_content` thay thế, `read_multiple_files`, `read_media_file` — không dùng thực tế, dễ thêm lại nếu cần). Tên tool giữ nguyên `local__*` (áp qua wrapper trong `tools-server.js`, không đổi tên lần hai). RAM/session-churn/OAuth flow thực tế chưa đo lại trên máy thật — việc của owner, không tự chạy `npm start`.
